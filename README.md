# Khipro - Windows Portable

## About Khipro

Khipro is the first compositional lowercase keyboard layout concept for Bengali, designed to be the fastest typing method for Bengali. It uses a fixed-phonetic approach where you type Latin characters and they are composited into Bengali script in real time.

The input method engine is implemented by the cross-platform [khipro library](https://github.com/KhiproTeam/khipro-library). This repository is a Windows portable build that wraps the same engine into a standalone system tray application — no installer, no dependencies, just run the exe.

## Usage

1. Download `khipro.exe` from the [latest release](https://github.com/KhiproTeam/khipro-windows-portable/releases/latest)
2. Run it — a tray icon appears in the system tray
3. **Toggle on/off:**
   - `Ctrl+Space`
   - Left-click the tray icon
   - Right-click the tray icon and select Active/Inactive
4. **Switch layout (Classic / Dark):** right-click the tray icon and pick one — the radio dot marks the active layout.
5. **Change the shortcut:** right-click the tray icon → **Change shortcut (…)** → press the new combination (must include Ctrl, Alt or Win). `Esc` cancels, and waiting times out after 10 seconds. If another app already uses the combo, you can try again immediately.
6. **Exit:** Right-click the tray icon and select Exit
7. **Auto-start on login:** `Win+R` > type `shell:startup` > copy `khipro.exe` into that folder
8. Hover the tray icon to see versions, the active layout, and status

## Configuration

`khipro.cfg` is created next to the exe on your first layout or shortcut change:

```
layout=classic        # classic | dark
hotkey=ctrl+space     # mods: ctrl alt shift win · keys: A-Z, 0-9, F1-F24, space, tab, enter, ...
```

Both lines are optional; a missing, garbled, or rejected line falls back to the default (Classic, `Ctrl+Space`). Delete the file to reset everything.

## Versioning

Hover the tray icon — the tooltip shows four independent version numbers:

```
Khipro - Compositional Bangla Layouts
Version: 1.8 · Library: 2.0.0 · Classic: 37.0.1 · Dark: 1.1.0
Classic · Inactive
```

- **Version** (e.g. `1.8`) — this portable's own version, defined in [src/resources.h](src/resources.h) (`KHIPRO_PORTABLE_VERSION`), independent of the library. A release tag is exactly `v` + this version. The **sync-library** workflow bumps the minor automatically when it vendors a library update; bump it yourself for portable-only releases.
- **Library** (e.g. `2.0.0`) — the [khipro library](https://github.com/KhiproTeam/khipro-library) release the exe was built against, from `khipro_library_version()`.
- **Classic** / **Dark** (e.g. `37.0.1` / `1.1.0`) — the layout spec versions compiled into this exe.

Each release is tagged exactly `v<version>` (e.g. `v1.8`) — find your exe's release on the [releases page](https://github.com/KhiproTeam/khipro-windows-portable/releases). Older releases (≤ October 2026) used composite `<library>-<portable patch>` tags such as `v36.5.0-0-1`.

Every release post carries a **"Shipped in this exe"** table (library + Classic + Dark versions), generated by CI from the vendored header — CI refuses to publish without it.

## Build

The library artifact (`khipro.h` + `libkhipro.a`) is **vendored** in [`resources/khipro/`](resources/khipro) and checked into the repo, so `make` works fully offline — no network access or `gh` auth required.

**Prerequisites:** `g++-mingw-w64-x86-64` and `gcc-mingw-w64-x86-64` for cross-compiling. (Add `gh`, `curl`, `unzip` only if you intend to refresh the vendored library.)

```
make          # offline cross-compile → khipro.exe (release build — no debug logging)
make debug    # developer diagnostic build → also logs the hotkey/capture flow to khipro.log
```

`make debug` is for local debugging only; CI always builds the release path, so released exes never contain the debug logging.

### Refreshing the vendored library

To pull the latest release from [KhiproTeam/khipro-library](https://github.com/KhiproTeam/khipro-library/releases) and overwrite `resources/khipro/`:

```
make update-lib
```

This downloads `khipro-<version>-windows-x86_64.zip`, extracts only the header + static lib, and updates `resources/khipro/.tag`. Review the diff and commit. CI also runs this automatically on the daily poll when a new library tag is detected.

### Workflows

Two single-purpose workflows keep releases automatic:

- **[sync-library](.github/workflows/sync-library.yml)** — daily cron + manual dispatch. When [khipro-library](https://github.com/KhiproTeam/khipro-library) publishes a new release, it vendors it into `resources/khipro/`, bumps `KHIPRO_PORTABLE_VERSION` in `src/resources.h` (minor bump, `1.8` → `1.9`), and pushes one commit. Nothing else.
- **[release](.github/workflows/release.yml)** — on push to `main` touching `src/**` or `resources/khipro/**`, plus manual dispatch. It reads the version from `src/resources.h` and publishes a release tagged `v<version>` — **only if that tag doesn't exist yet**. So a version bump is what cuts a release: a push whose `v<version>` already exists is skipped.

Beta handling: when the vendored library tag is a pre-release, the portable publishes as a pre-release too, never marked as "latest" — the [latest release](https://github.com/KhiproTeam/khipro-windows-portable/releases/latest) link always points at the newest stable build. A newer stable release wins again.

Every release post shows a **"Shipped in this exe"** table (library + Classic + Dark versions — CI refuses to publish without them) and a **Full Changelog** compare link. For announcements beyond that, edit the post on GitHub after publishing.
