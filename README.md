# Khipro - Windows Portable

## About Khipro

Khipro is the first compositional lowercase keyboard layout concept for Bengali, designed to be the fastest typing method for Bengali. It uses a fixed-phonetic approach where you type Latin characters and they are composited into Bengali script in real time.

The input method engine is implemented by the cross-platform [khipro library](https://github.com/KhiproTeam/khipro-library). This repository is a Windows portable build that wraps the same engine into a standalone system tray application — no installer, no dependencies, just run the exe.

## Usage

1. Download `khipro.exe` from the [latest release](https://github.com/KhiproTeam/khipro-windows-portable/releases/latest)
2. Run it — a tray icon appears in the system tray
3. **Toggle on/off:**
   - `Ctrl+Space`
   - Left-click the tray icon
   - Right-click the tray icon and select Active/Inactive
4. **Switch layout (Classic / Dark):** right-click the tray icon and pick one — the radio dot marks the active layout. Your choice is remembered in `khipro.cfg` next to the exe, created automatically on the first switch.
5. **Exit:** Right-click the tray icon and select Exit
6. **Auto-start on login:** `Win+R` > type `shell:startup` > copy `khipro.exe` into that folder
7. Hover the tray icon to see versions, the active layout, and status

## Versioning

Hover the tray icon — the tooltip shows four independent version numbers:

```
Khipro - Compositional Bangla Layouts
Version: 1 · Library: 2.0.0 · Classic: 37.0.1 · Dark: 1.1.0
Classic · Inactive
```

- **Version** (e.g. `1`) — this portable's own release counter. Every release increments it (`v1`, `v2`, `v3`, …), whether the trigger was a library update or a portable change. It is independent of the library version. Local `make` builds without stamping report `dev`.
- **Library** (e.g. `2.0.0`) — the [khipro library](https://github.com/KhiproTeam/khipro-library) release the exe was built against, from `khipro_library_version()`.
- **Classic** / **Dark** (e.g. `37.0.1` / `1.1.0`) — the layout spec versions compiled into this exe.

Each release is tagged `v<counter>` (e.g. `v1`) — find your exe's release on the [releases page](https://github.com/KhiproTeam/khipro-windows-portable/releases). Older releases (≤ October 2026) used composite `<library>-<portable patch>` tags such as `v36.5.0-0-1`.

**Local build stamping:** `make PORTABLE_VERSION=9` stamps `Version: 9`; plain `make` reports `dev`.

Every release post carries a **"Shipped in this exe"** table (library + Classic + Dark versions), generated by CI from the vendored header — CI refuses to publish without it.

## Build

The library artifact (`khipro.h` + `libkhipro.a`) is **vendored** in [`resources/khipro/`](resources/khipro) and checked into the repo, so `make` works fully offline — no network access or `gh` auth required.

**Prerequisites:** `g++-mingw-w64-x86-64` and `gcc-mingw-w64-x86-64` for cross-compiling. (Add `gh`, `curl`, `unzip` only if you intend to refresh the vendored library.)

```
make          # offline cross-compile → khipro.exe
```

### Refreshing the vendored library

To pull the latest release from [KhiproTeam/khipro-library](https://github.com/KhiproTeam/khipro-library/releases) and overwrite `resources/khipro/`:

```
make update-lib
```

This downloads `khipro-<version>-windows-x86_64.zip`, extracts only the header + static lib, and updates `resources/khipro/.tag`. Review the diff and commit. CI also runs this automatically on the daily poll when a new library tag is detected.

### CI release flow

[`.github/workflows/release.yml`](.github/workflows/release.yml) runs daily, on manual dispatch, and on push to `main` touching `src/**` or `resources/khipro/**`. The logic:

- **Push-triggered** → always releases under the next version counter (`v<n>` = last released + 1, tracked in `.release-tag`; the old composite tag format starts the counter at `v1`).
- **Schedule / dispatch** → releases only when the vendored library tag differs from the newest upstream release (beta or stable). A beta publishes as a pre-release, never marked as "latest" — the [latest release](https://github.com/KhiproTeam/khipro-windows-portable/releases/latest) link always points at the newest stable build. A newer stable release wins again.
- **The release commit carries `[skip ci]`** so it can never re-trigger the workflow.
- Release notes embed the shipped-versions table plus [.github/release-notes-extra.md](.github/release-notes-extra.md) when that file exists (edit it before a release to add announcements; trim it afterwards).
